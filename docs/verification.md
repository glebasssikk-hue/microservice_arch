# Проверка комплекта
Дата: 09.11.2026. Проверяется архитектура, не работающее приложение.

## Прослеживаемость
| Требование/инвариант | Где обеспечивается | Как проверить во второй части |
|---|---|---|
| I1: одна машина одному процессу | Fleet, ADR-005 | Два конкурентных ReserveVehicle: ровно один VehicleReserved |
| I2: одна незавершённая аренда пользователя | Rental, частичная уникальность | Два POST с разными ключами: один принят, другой 409 |
| I3: доступ после холда | Порядок Saga, GrantAccess | До DepositHeld нет GrantAccess |
| I4: один холд | Payment, ADR-004 | 10 повторов, один эффект в симуляторе банка |
| I5: ACTIVE после подтверждения | Rental, success.mmd | Принятый, но не исполненный grant не даёт ACTIVE |
| I6: UNKNOWN удерживает ресурс | Access, failure-access.mmd | Потерять ответ после выдачи: машина не AVAILABLE |
| I7: безопасная отмена | Процесс компенсации | После CANCELLED отсутствуют холд, доступ и выделение |
| I8: timeout не равен отказу | reliability.md | Банк выполнил холд и потерял ответ: сначала сверка |
| I9: поздний grant запрещён | CLOSED, epoch, tombstone | Доставить grant после revoke: состояние остаётся CLOSED |
| I10: устойчивое продолжение | Saga, Outbox, Inbox | Убить Rental до ACK; после перезапуска один итоговый переход |

## Дополнительные мысленные проверки
- Отмена до резервирования: tombstone запрещает поздний резерв.
- Отмена до холда: Payment фиксирует желаемое RELEASED; поздний холд не возобновляется.
- Успех и таймер одновременно: CAS состояния выбирает один переход; CANCELLING не становится ACTIVE от позднего события.
- Ошибка снятия холда: процесс не помечается CANCELLED; сверка продолжается.
- Истёкший hold до выдачи: grant не отправляется, начинается компенсация.
- Автомобиль движется: нет удалённого глушения, требуется разбор.
- Потеря Outbox publish-confirm: возможен дубль, обработка идемпотентна.

## Проверяемые формальные свойства
Контракты проходят специализированные валидаторы OpenAPI и AsyncAPI. Все шесть исходников Mermaid должны успешно рендериться. Локальные ссылки Markdown должны разрешаться. Имена асинхронных сообщений в sequence-диаграммах сверяются с AsyncAPI.
Результаты фактического запуска проверки приводятся в validation-results.md. Архитектурный разбор не доказывает корректность будущей реализации и не заменяет испытания отказов.
