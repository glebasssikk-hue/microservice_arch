# ADR-004. Идемпотентность и неизвестный внешний результат
Статус: принято. Дата: 09.11.2026.

## Контекст
Банк или машина могут выполнить команду и потерять ответ. Повтор с новым ключом создаст новый эффект, а слепая отмена может выдать машину другому.

## Варианты
Считать timeout отказом; бесконечно повторять с новыми ID; стабильные операции и сверка.

## Решение
Стабильный operationId, durable registry до сетевого вызова, GET результата, терминальный revoke/release, sessionId и fencing epoch. UNKNOWN сохраняется. Для неопределённости MANUAL_REVIEW; ресурс не освобождается автоматически.

## Последствия
Плюсы: повторы безопасны при выполнении требований внешними системами. Минусы: требуются достаточно сильные API провайдеров, ручное разбирательство и временная потеря доступности. Идемпотентность нашей БД не заменяет идемпотентность банка.

## Когда пересмотреть
Провайдер без поиска по ключу или терминального отзыва требует другого протокола; обещать прежние гарантии нельзя.
