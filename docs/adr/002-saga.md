# ADR-002. Оркестрируемая Saga
Статус: принято. Дата: 09.11.2026.

## Контекст
Запуск проходит через Fleet, банк и автомобиль; общей ACID-транзакции нет. Нужны видимые промежуточные состояния и восстановление.

## Варианты
Синхронная цепочка HTTP; хореография; оркестрация; 2PC.

## Решение
Rental хранит Saga, таймеры и шаги в PostgreSQL; команды и результаты идут через брокер. Участники выполняют локальные транзакции. Компенсации выполняются в безопасном порядке.

## Последствия
Плюсы: понятный ход процесса, удобная защита и диагностика. Минусы: Rental знает шаги всех участников и временно останавливает новые переходы при отказе. Несколько экземпляров используют блокировку/version; памяти процесса недостаточно. 2PC не поддерживается физическим автомобилем.

## Когда пересмотреть
При росте числа процессов оценить специализированный workflow engine; для одного учебного процесса достаточно явной машины состояний.
