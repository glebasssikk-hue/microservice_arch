# Надёжность, безопасность и восстановление
## Локальная атомарность
При обработке команды/события одна транзакция включает Inbox, бизнес-изменение и Outbox следующих сообщений. Relay публикует с publisher confirm и помечает запись доставленной. Сбой между publish и отметкой создаёт дубль: это ожидаемое поведение. ACK входного сообщения только после commit. Outbox не делает сетевой эффект банка атомарным с БД.

Перед банковским вызовом Payment сохраняет operationId и PENDING. После сбоя запрашивает результат у провайдера по тому же operationId. Access действует аналогично. Дубликат в Inbox не должен остановить незавершённую внешнюю работу: её продолжает worker из устойчивого реестра операций.

## Конкурентность и идентификаторы
messageId — конкретное сообщение; correlationId = rentalId — весь процесс; operationId — логическое действие. Retry сохраняет operationId, даже если новое транспортное сообщение имеет новый messageId. causationId ссылается на причину. Схема сообщения version=1.

Операции имеют детерминированные ключи: rentalId:reserve, :hold, :grant, :revoke, :release-hold, :release-vehicle. Fleet повышает epoch при каждом новом выделении машины. Access/телематика не принимают старый epoch после нового и не возобновляют CLOSED sessionId.

В Fleet блокировка строки машины плюс уникальность открытого выделения сериализуют конкурирующие запросы. Rental использует частичную уникальность userId среди незавершённых аренд; проверка SELECT до INSERT без ограничения недостаточна.

HTTP ключ ограничен userId + route + key. Повтор с тем же телом возвращает тот же rentalId/Location и первоначальный 202; актуальный статус читается GET. Другое тело с тем же ключом — 409 IDEMPOTENCY_CONFLICT. Новый ключ не обходит ограничение активной аренды пользователя.

## Доставка
AMQP 0-9-1 с TLS; direct exchanges drive.commands.v1 и drive.events.v1. Routing keys — адреса каналов AsyncAPI. Командные очереди по владельцу, события результатов — очередь Rental. Durable quorum queues, persistent messages, publisher confirms, manual ACK.
Повторы транспортных ошибок: через 1, 5, 15, 30, 60 с, затем DLQ и сигнал. Бизнес-отказ не ретраится. Replay из DLQ сохраняет operationId и проверяет актуальное состояние Saga. DLQ не является компенсацией. При недоступном брокере Outbox копит записи; новые запуски ограничиваются при превышении очереди, принятые процессы продолжаются после восстановления.

## Внешние предпосылки
Банк должен поддерживать идемпотентный холд, поиск операции по ключу и снятие холда. Телематика должна поддерживать sessionId, idempotency, epoch, validUntil, поиск результата и терминальный отзыв. Это требования к адаптерам/симуляторам второй части; они не утверждают наличие таких функций у произвольного коммерческого API.
Без терминального отзыва нельзя безопасно освободить автомобиль после потерянного ответа. Такой провайдер не подходит без дополнительного протокола или ручной проверки.
validUntil проверяется на устройстве/платформе при исполнении, не только у нас перед отправкой. Часы синхронизированы; допуск рассинхронизации 5 с. Холд должен действовать минимум 30 минут для запуска; если срок истёк до grant, запуск отменяется. Срок покрытия всей поездки — отдельное решение будущего расчётного процесса.

## Сбой компенсации
При сбое RevokeAccess не снимаем защитное выделение. При сбое ReleaseDeposit после подтверждённого отзыва повторяем сверку банка, машину по выбранной консервативной политике пока удерживаем. VehicleReleased возвращает AVAILABLE только при технической пригодности; иначе OUT_OF_SERVICE. После 15 минут — MANUAL_REVIEW. Компенсация продолжается после перезапуска; нет бесконечного цикла в HTTP-запросе.

## Оператор и наблюдаемость
Метрики: возраст Saga, старейший Outbox, количество UNKNOWN, DLQ, задержка шагов, время компенсации. В журнале: rentalId, operationId, messageId, state, version, providerRef; карточные токены и документы маскируются.
При MANUAL_REVIEW оператор проверяет журнал, обращается к телематике и банку по исходным идентификаторам, связывается с водителем. После подтверждения CLOSED и RELEASED разрешает повтор исходных компенсаций. Прямой SQL-перевод в AVAILABLE запрещён. Если автомобиль использован — отдельный инцидент и расчёт фактического использования, а не фиктивная отмена.

## Доступ и защита
JWT проверяется по подписи, issuer, audience, exp. Rental выводит userId из sub; чужой rentalId возвращает 404. Внутренние брокерные ACL разрешают команды только соответствующим сервисам; клиент не публикует GrantAccess. PaymentMethodToken — непрозрачный токен провайдера, должен принадлежать пользователю. TLS, отдельные секреты и роли баз. Учебная авторизация не является заявлением о сертификации платежей.

## Резервное копирование
Outbox защищает от сбоя приложения, но не от потери диска. Для будущего развёртывания: резервные копии PostgreSQL и журналирование WAL, репликация брокера, учебное упражнение восстановления. Нулевые RPO/RTO не обещаются. После восстановления из старой копии новые выдачи приостанавливаются до сверки с банком и телематикой.
