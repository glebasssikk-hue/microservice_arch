# Главный процесс — начало аренды
Вход: POST /rentals с vehicleId, paymentMethodToken и Idempotency-Key. userId берётся из JWT. Предусловия: допуск APPROVED, срок действия допуска не истёк, нет незавершённой аренды пользователя. Депозит фиксирован: 500000 копеек, RUB (учебное допущение, не рыночная рекомендация). Он берётся с сервера, клиент сумму не задаёт.

1. Rental в одной транзакции сохраняет STARTING, шаг RESERVING и Outbox ReserveVehicle. Возвращает 202 с rentalId и Location.
2. Fleet атомарно закрепляет пригодную машину; создаёт allocationId и увеличивает epoch. VehicleReserved содержит оба значения. Конкурент получает VehicleReservationRejected.
3. Rental сохраняет результат и отправляет HoldDeposit; Payment подтверждает HELD либо явный отказ.
4. Rental отправляет GrantAccess с allocationId, epoch, holdId и validUntil. Access хранит намерение до обращения к машине.
5. AccessGranted подтверждает действующее право доступа. Rental сохраняет ACTIVE и startedAt, равный effectiveAt телематики. При сильно запоздавшем событии Access сначала сверяет состояние.
6. Клиент опрашивает GET /rentals/{rentalId}. Отдельный сервис уведомлений не нужен.

Асинхронные стрелки между сервисами на sequence-диаграммах сокращённо показывают доставку через RabbitMQ. Локальные изменения и Outbox атомарны; ACK сообщения — после commit. Синхронные стрелки к внешним системам — HTTPS. Все сообщения имеют определения в AsyncAPI.

## Состояния
Внешние состояния Rental: STARTING, ACTIVE, CANCELLING, CANCELLED, MANUAL_REVIEW.
Внутренний step: RESERVING, HOLDING, GRANTING, REVOKING, RELEASING_HOLD, RELEASING_VEHICLE, DONE.
MANUAL_REVIEW — состояние расследования, не успешный и не окончательный бизнес-результат; резерв и блокировка пользователя сохраняются.
Fleet: AVAILABLE, ALLOCATED, OUT_OF_SERVICE. ACTIVE не дублируется во Fleet: наличие выделения уже запрещает конкурентную аренду.
Payment: PENDING, HELD, RELEASING, RELEASED, REJECTED, UNKNOWN.
Access: PENDING, GRANTED, REVOKING, CLOSED, UNKNOWN. CLOSED терминален для sessionId.

## Отмена и порядок компенсаций
До отправки GrantAccess достаточно закрыть возможный холд, затем выделение. После отправки GrantAccess, даже если ответа нет: RevokeAccess → AccessRevoked → ReleaseDeposit → DepositReleased → ReleaseVehicle → VehicleReleased → CANCELLED.
Отзыв доступа включает запрет позднего GrantAccess; просто закрыть двери недостаточно. Нельзя отзывать доступ так, чтобы заглушить движущийся автомобиль. При признаках начатой поездки — MANUAL_REVIEW и связь с водителем; автоматического освобождения нет.

ReleaseDeposit и ReleaseVehicle являются «обеспечить отсутствие», работают даже если исходная команда ещё не дошла. Они записывают терминальное намерение отмены. Поздняя исходная команда получает отказ; если внешний холд уже был отправлен, Payment сначала сверяет его, затем снимает. Rental не считает отсутствие локальной записи доказательством отсутствия внешнего эффекта.

После 60 с ожидания любого шага запускается проверка/компенсация. Это не TTL выделения. После 15 минут неразрешённой операции — MANUAL_REVIEW и сигнал оператору; фоновая сверка продолжается. Пока нет доказательства безопасности, нет обещанного срока освобождения ресурса.

## Гонка успеха с таймаутом
Rental обрабатывает событие и таймер с version/CAS одной строки Saga. Если ACTIVE зафиксирован первым, таймер запуска уже не действует. Если первым зафиксирован CANCELLING, поздний AccessGranted не переводит аренду в ACTIVE: выполняется отзыв, а при фактической поездке — разбирательство. Пользователь до ACTIVE видит «запуск подтверждается» и не должен начинать поездку.

## Остальные результаты и таймауты
| Ожидание / результат | Следующее действие |
|---|---|
| RESERVING / VehicleReservationRejected | Закрыть намерение выделения через ReleaseVehicle, затем CANCELLED; холд ещё не отправлялся |
| RESERVING / таймаут | CANCELLING, ReleaseVehicle по rentalId, даже если allocationId пока неизвестен |
| HOLDING / DepositUncertain или таймаут | CANCELLING, ReleaseDeposit по исходному holdOperationId; ждать доказанного DepositReleased, затем ReleaseVehicle |
| HOLDING / DepositHeld с недостаточным сроком действия | Та же компенсация; GrantAccess не отправлять |
| GRANTING / AccessRejected | RevokeAccess для терминального закрытия сессии, затем снятие холда и выделения |
| GRANTING / таймаут или AccessUncertain | Сценарий failure-access.mmd |
| Любой шаг компенсации / таймаут | Сверка и повтор той же логической операции, после 15 минут MANUAL_REVIEW |
| MANUAL_REVIEW / доказанный результат | Продолжить ранее выбранное направление Saga; автоматического переключения отмены в успех нет |

События, не соответствующие ожидаемому шагу, журналируются и проверяются. Нельзя игнорировать поздний внешний успех, если он требует компенсации. После завершённой отмены терминальные записи участников не позволяют повторно открыть ресурс.
